# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

MiniBot: a ChatGPT-style LLM agent. pnpm workspace + Turborepo monorepo:

- `apps/web` — Next.js 16 (App Router, React 19, Tailwind v4, shadcn/ui). Serves both UI and API.
- `packages/agent` — the pi-agent (`@earendil-works/pi-*`) Agent: DeepSeek model, system prompt, tools.
- `packages/sandbox` — dockerode-based per-conversation Docker sandbox lifecycle.
- `packages/db` — Drizzle schema, client, SQL migrations (PostgreSQL).

Internal packages are "just-in-time": they export TS source (`exports` → `./src/*.ts`) and are compiled by Next via `transpilePackages`. There is no per-package build step. Dependency direction: `web → agent → sandbox`, `web → db`. `agent` knows nothing about HTTP/DB; `sandbox` knows nothing about LLMs.

`apps/web/AGENTS.md` (regenerated by `next dev`, keep it committed) warns that Next.js 16 differs from older versions — consult `apps/web/node_modules/next/dist/docs/` before using unfamiliar Next APIs. Notably middleware is `src/proxy.ts` (exported `proxy` function).

## Commands

```bash
pnpm install
docker compose up -d db          # Postgres only (for local dev)
pnpm db:migrate                  # apply migrations (reads root .env)
pnpm sandbox:build               # build minibot-sandbox:latest image
pnpm dev                         # Next dev server on :3000

pnpm check                       # format:check + lint + typecheck + test (all packages, via turbo)
pnpm lint | pnpm typecheck | pnpm test
pnpm --filter @minibot/web build # production build

# single test file / single test
pnpm --filter @minibot/web exec vitest run src/lib/chat/ui-messages.test.ts
pnpm --filter @minibot/web exec vitest run -t "findTurnEnd"
# e2e (Playwright, system Chrome; needs a running app on :3000, chat tests need DEEPSEEK_API_KEY)
pnpm --filter @minibot/web test:e2e

# schema changes: edit packages/db/src/schema/*, then
pnpm db:generate                 # writes SQL to packages/db/drizzle/ — commit it

# full deployment
docker compose up -d --build
```

`packages/agent/src/tools/sandbox.integration.test.ts` runs against real Docker and auto-skips if the `minibot-sandbox:latest` image is missing.

## Environment

A single `.env` at the repo root (see `.env.example`) is shared by everything: `next.config.ts` and `packages/db/src/env.ts` load it with `process.loadEnvFile`. Env is validated with zod in `apps/web/src/env.ts`; `SKIP_ENV_VALIDATION=1` is used for Docker builds, so server modules must not use secrets at import time (see the lazy key in `server/crypto.ts`). `DEEPSEEK_API_KEY` is an optional server-wide fallback; users normally store their own key (AES-256-GCM encrypted) via Settings.

## Chat request flow (spans several files)

1. Client `components/chat/chat.tsx` uses AI SDK `useChat` with a custom `prepareSendMessagesRequest` that sends only `{ trigger, conversationId, message | messageId }` — the DB is the source of truth for history. Conversation ids are generated client-side; a new chat at `/` swaps the URL to `/c/<id>` via `history.replaceState`, and the row is created on the first message.
2. `app/api/chat/route.ts` → `server/chat/run-chat.ts`: auth, load settings, in-memory one-run-per-conversation lock (409), persist user message (or truncate for regenerate), then `createMiniBotAgent({ history })` and `agent.continue()`.
3. `server/chat/event-mapper.ts` translates pi `AgentEvent`s into AI SDK UI message stream chunks (tools are sent as `dynamic` tools; provider errors as a `data-error` part). Keep it in sync with `lib/chat/ui-messages.ts`.
4. Every assistant/toolResult message is inserted on `message_end`, so aborts (client disconnect → `request.signal` → `agent.abort()`) keep partial progress.

Persistence model: table `message` stores each pi `AgentMessage` verbatim as JSONB with a per-conversation `seq`. `lib/chat/ui-messages.ts#toUIMessages` groups consecutive assistant/toolResult rows into one UI assistant message whose id is the **first row's id** — that id is the anchor for fork (`findTurnEnd`) and regenerate. The streamed assistant message reuses a pre-generated id so this holds without a reload.

CRUD (rename/archive/delete/fork, settings) goes through Server Actions in `src/actions/*` (zod-validated, `requireUser()`), which call `server/services/*` and `revalidatePath("/", "layout")`. Fork also copies the sandbox `/workspace` to the new conversation.

## Agent & sandbox specifics

- Models/thinking levels live in `packages/agent/src/catalog.ts`, which is dependency-free. **Client components must import from `@minibot/agent/catalog`**, never `@minibot/agent` (the main entry pulls Node-only pi-coding-agent into the browser bundle and breaks the build). Type-only imports from `@minibot/agent` are fine.
- Sandbox tools reuse pi-coding-agent's `create*Tool` implementations with custom `operations` backed by `docker exec` / `putArchive`. pi's grep always spawns a local `rg`, so `grep` is a custom tool that runs ripgrep in the container. Sandbox tools are forced to `executionMode: "sequential"` because they share a filesystem.
- Web tools call DeepSeek Search/Fetch (`/v1/tools/search`, `/v1/tools/fetch`) with the user's key.
- `Sandbox.exec` runs commands under `setsid` and records the PGID so timeout/abort can kill the whole process group. Containers: one per conversation (`minibot-sbx-<id>`), non-root, `CapDrop: ALL`, `no-new-privileges`, resource limits, network `none` by default; idle ones are stopped by a reaper.
- Locally dockerode uses `/var/run/docker.sock`; in Compose the web container uses `DOCKER_HOST=tcp://docker-proxy:2375` (docker-socket-proxy), never the raw socket.
- Singletons (`server/db.ts`, `server/sandbox.ts`, the active-run set) are cached on `globalThis` to survive dev hot reloads.

## Conventions

- Conventional Commits, enforced by commitlint (`commit-msg` hook); `pre-commit` runs lint-staged (eslint --fix + prettier).
- Server-only modules start with `import "server-only"`.
- ESLint: root `eslint.config.js` for packages; `apps/web/eslint.config.js` composes Next's presets with the shared `sharedRules`. `src/components/ui/**` (shadcn-generated) is excluded from lint/format — add components with `pnpm dlx shadcn@latest add <name>` in `apps/web` (if behind an HTTP proxy, unset `http_proxy`/`https_proxy`, shadcn's proxy handling fails).
- pnpm 11 policies in `pnpm-workspace.yaml`: dependency install scripts must be allow-listed in `allowBuilds`; packages younger than `minimumReleaseAge` must be added to `minimumReleaseAgeExclude` (pi packages are pinned to exact versions).
- TypeScript is pinned to 6.0.x because typescript-eslint does not support 7.x yet.
